The problem

Every language is a silo.

Code written for the web stays on the web. Code written in Swift only runs on iPhones. The same idea has to be rebuilt from scratch for every platform — or squeezed through one-size-fits-all frameworks that never quite feel native.

So I built my own compiler. The Universal App Compiler takes code in any language, translates it once into a Universal App Schema, and emits real native iOS and Android apps from the same source. Write it once, in whatever language you think in — the compiler does the translating.

How it works

Paste code. Pick targets. Build.

The builder opens with a source editor that accepts six input languages: React, Swift, Java, Kotlin, Python, or plain English. Below it, target toggles select iOS and/or Android. One button — "Build my app" — compiles the source into native output for the selected targets.

The key insight is the middle step: everything funnels through a Universal App Schema, a shared intermediate representation of the app's screens, logic, and assets. New input languages and new output targets become translation problems, not rewrites.

📝 Six input languagesReact, Swift, Java, Kotlin, Python, or plain English — paste code or describe the app, and the compiler figures out the intent.
📱 iOS and Android targetsToggle one platform or both. The same source produces real native apps for each selected target.
🧩 Universal App SchemaA translation layer between any source and any native output — parsed once, emitted natively per target.
▶️ One build button"Build my app" compiles source into native apps. No wrappers, no web views — native output.

Why it matters

A compiler, not a template.

The interesting part of UAC isn't the six input languages — it's the schema in the middle. A universal intermediate representation means the system improves multiplicatively: adding a new input language immediately works for every output target, and adding a new target immediately works for every input language.

That's what makes "any code in, native app out" a compiler instead of a template. I built UAC for myself because I wanted to think in whatever language was fastest for the idea at hand — and still ship native apps on both platforms.
