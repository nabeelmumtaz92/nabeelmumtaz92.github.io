Personal Project · Remote Desktop

Portal. My Mac, in my pocket.

A remote desktop system I built for myself — it streams my Mac's screen to my iPhone app and any laptop browser in real time, with full mouse, keyboard, and clipboard control from anywhere. 1080p at up to 60 frames per second.

The problem

I wanted my whole computer with me, everywhere.

Off-the-shelf remote desktop tools work — until they don't. Laggy frame delivery, clumsy touch input, a third party sitting in the middle of the connection, and no control over the experience. I use my Mac for real work, and I wanted to reach it from my phone or any laptop and have it feel like sitting at the desk.

So I built my own. Portal is a full remote desktop pipeline: capture, encode, transport, decode, and input — engineered end to end by one person, tuned for the way I actually work.

The architecture

Hardware on both ends, nothing wasted in the middle.

Frames are captured with ffmpeg on the Mac, encoded to H.264 on the Mac's hardware encoder, and sent over WebSockets through a Node.js server. Decoding happens in hardware too — AVSampleBufferDisplayLayer on iOS, WebCodecs in the browser. No software codec ever touches the hot path.

Two clients share one pipeline: a native iPhone app (Swift, SwiftUI, UIKit) and an installable browser client. Input flows back the other way — mouse, keyboard, clipboard, and touch gestures — validated strictly on the server before anything reaches the machine.

The hard problems were latency, not pixels. Anyone can stream a screen. Making it feel local — fast reconnects, no rubber-banding on bad networks, touch input that doesn't fight you — is where all the engineering went.

Key engineering

What it took to make it feel local.

🖥️ 1080p at up to 60 fpsHardware H.264 encoding on the Mac, hardware decoding on iOS and in browsers. The full desktop, fluid.
📉 Adaptive congestion controlRound-trip probing plus adaptive bitrate — on a struggling network it skips to the next keyframe instead of lagging. Worst-case lag went from 7.3s to 2.1s on a simulated 1.5 Mbps connection.
⚡ ~6 ms reconnectsWarm capture plus cached frames since the last keyframe. Dropped connections resume in about 6 ms on a local network, down from ~800 ms.
👆 iPhone input that feels nativeTouch and trackpad input modes with pointer acceleration, momentum scrolling, and pinch-zoom. The iPhone keyboard auto-opens when a Mac text field gains focus (via the macOS Accessibility API), with two-way clipboard sync and multi-monitor switching.
🌐 Browser clientAn installable web app for any laptop — full mouse, keyboard, and clipboard control, with Windows shortcuts mapped to Mac equivalents (Ctrl → ⌘).
🔒 Hardened by defaultHTTPS via Tailscale Funnel, constant-time token checks, per-device lockout on repeated wrong codes, and strict server-side validation of all remote input against command injection.

Shipping it to one user

No App Store. No cable. Just works.

Portal runs as a macOS background service (launchd) on my machine. The iPhone app installs over the air and checks for updates in-app — the whole system stays current with zero ceremony. I built it for exactly one user, and that user opens it every day.
